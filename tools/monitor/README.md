# monitor

데이터 처리부의 빔 스케줄링, 트랙, 상대 연결 상태를 보여주는 모니터 프로그램입니다.
모의기는 시나리오 참값을, 전시기는 예측 트랙만 보여주므로 그 사이에서 처리부가
내린 판단을 확인하는 용도입니다.

## 실행

Python 3.8 이상의 표준 라이브러리만 사용합니다. 별도 패키지 설치는 필요하지 않습니다.
Linux에서는 tkinter 패키지(`python3-tk`)가 따로 필요할 수 있습니다.

`tools/monitor` 디렉터리에서 처리부와 같은 `.env` 파일을 지정해 실행합니다.

```sh
cd tools/monitor
python -m monitor --env ../../.env
```

| 옵션 | 설명 |
| --- | --- |
| `--env PATH` | 처리부와 같은 `.env` 파일. 기본값은 현재 디렉터리의 `.env` |
| `--server ADDRESS:PORT` | 처리부 서버 주소. `.env`의 `COMM_SERVER_*`를 덮어씀 |
| `--local ADDRESS:PORT` | 모니터가 바인딩할 주소. `.env`의 `COMM_MONITOR_*`를 덮어씀 |
| `--headless` | 화면 없이 1초마다 수신 요약을 출력 |
| `--duration SECONDS` | `--headless`에서 지정한 시간만큼 실행 후 종료 |

처리부는 수락한 연결을 원격 주소와 포트로 구분합니다. 그래서 모니터는
`COMM_MONITOR_ADDRESS:COMM_MONITOR_PORT`에 바인딩한 뒤 접속하며, 이 주소가
처리부 설정과 다르면 연결이 거부됩니다. 연결이 끊기면 1초마다 다시 접속합니다.
모니터는 처리부에 아무것도 보내지 않습니다.

## 화면

- 상단 바: 처리부, 운용통제기, 모의기 연결 상태와 처리부 시각, 속도, 레이더 자세
- 빔 방향: 받은 빔의 방위·고각을 그립니다. 탐색 빔은 칸의 잔상으로, 확인·추적 빔은 빔 폭 크기의 원으로 표시합니다.
- 빔 점유율: 최근 5초 동안 빔 종류별 비율
- 탐색 한 바퀴: 같은 탐색 칸을 다시 방문하기까지 걸린 처리부 시간
- 최근 빔: 최근 송신한 빔 목록
- 빔 타임라인: 처리부 시각 기준으로 빔 종류별 색 띠를 표시합니다.
- 트랙: 처리부가 전시기에 보내는 확정 트랙 목록

보기는 자동, 상세, 흐름 중에서 고릅니다. 자동은 처리부가 정지했거나 속도가
×0.25 이하이면 상세 보기를, 그 밖에는 흐름 보기를 사용합니다. 상세 보기는 잔상과
타임라인 구간을 짧게 하고 가장 최근 탐색 칸을 강조합니다.

모든 시간 계산은 처리부 시각을 기준으로 하므로 처리부 속도를 바꿔도 점유율과
탐색 한 바퀴 시간이 같은 값으로 표시됩니다.

## 수신 메시지

처리부는 다른 상대에 보내는 메시지의 복사본과 모니터 전용 상태 메시지를 보냅니다.
배치는 `src/comm/src/protocol`의 구조체와 같으며 `monitor/protocol.py`에 정의되어 있습니다.

| 메시지 ID | 구조체 | 내용 |
| --- | --- | --- |
| `0xAB01` | `ST_BeamTxMsg` | 모의기에 보낸 빔 송신 명령 |
| `0xAC01` | `ST_TrkMsg` | 전시기에 보낸 확정 트랙 목록 |
| `0xAC02` | `ST_RadarAttMsg` | 전시기에 보낸 레이더 자세 |
| `0xAD01` | `ST_MonitorStatusMsg` | 처리부 시각, 속도, 정지 여부, 운용통제기·모의기 연결 상태 (100ms 주기) |

## 테스트

```sh
cd tools/monitor
python -m unittest discover -s tests -t .
```

`test_protocol.py`는 C++ 헤더의 `static_assert` 크기와 메시지 ID를 읽어 파이썬 배치와 대조합니다.
