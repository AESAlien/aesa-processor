# 중간 속력 6표적 검증 계획

2026-11-17, 실제 다중 표적 로그를 취득하기 전에 작성했다.

- 시나리오: `scenarios/multi_target_moderate_6.ini` (CR 구분, 원본 복사·변형).
- 6개 표적, 250~320m/s, 초기 거리 42~90km, 고도 3500~10000m, 기동 0.2~0.4g.
- T1 직진, T2 우선회, T3 좌선회, T4 상승, T5 하강, T6 우선회 후 상승.
- 초기 heading은 0/90/270도다. 미확정인 105도 초기화 차이를 해결한 시험으로 해석하지 않는다.
- 0~99.8초를 0.499초 간격으로 예측한 표적 간 최소 거리는 약 5054m다. 실제 관측 결과가 아니다.
- 원본의 레이더 위치·자세·RCS 추정 필드와 100초 종료값은 유지했다. 모든 표적 시작 지연은 0이다.

`multi_target_moderate_frozen_candidate.json`은 기존 물리 규칙(순간 속력 결합 회전,
기준각 유지, 초기 속력으로 공칭 시간 계산, 0.1초 올림, 이산 수직 삼각 갱신)을 그대로 사용한다.
시계도 앞선 90도 단일 실험의 원점 0.01064606871776001초·주기 100.09847024568614초로 고정한다.
새 다중 표적의 운동·시계 계수를 맞추지 않고 두 운용 구간에 같은 옵션을 적용한다.
불일치 시 원본 잔차를 먼저 보고하며 별도의 진단 보정을 원래 검증과 구분한다.

환경은 Jammer·Clutter 항목 없음, Noise 고정 체크+0을 전송하고 확인한다.
전시기 Start → 모의기 모의 시작 순으로 각 운용 구간을 약 150초 이상 기록한다.
각 구간에서는 ini를 다시 불러오지 않으며 자동 반복을 주기 위상으로 처리한다.
두 번째는 운용을 정지 후 재시작한다. 프로그램 전체 재시작 시험과 구분한다.

플롯은 모델 잔차를 보기 전에 관측 위치·시간의 연속성으로 묶고, 분리된 공간 경로와 반복 경계를
검토해 표적에 대응시킨다. 처리부 추정 트랙이나 requestId를 정답 ID로 사용하지 않는다.
표본 수, 최대 관측 간격, 모호·미대응 행, 기동 중/후 R·Az·El·Doppler 잔차와 추세를 모두 기록한다.

원래 완료 기준인 초기 직진의 속력×20ms 최대 거리 오차와 무추세 여부도 그대로 판정한다.
이 속력에서는 한계가 5~6.4m라 기존 관측 산포만으로도 미충족할 수 있다.
새 시나리오가 조건부로 쓸 만한지 판단할 참고값으로 표적별 전체 거리 RMS 10m,
최대 30m, 거리 잔차 OLS 기울기 절대값 0.1m/s, 각도 RMS 0.02도,
도플러 RMS 0.5m/s와 비교하되, 이 참고값이 원래 완료 기준을 대체하지는 않는다.
관측 단절이나 기동 중 표본 부족은 성공으로 처리하지 않는다.

사용 가능 결론은 이 속력·기동·초기 방향 범위에 한정한다. 다른 heading, 급기동, 교차·근접 표적,
원본 전체 시나리오의 확정 정답이나 추적 성능 지표 검증으로 일반화하지 않는다.

## 예비 관측 후 정식 시나리오의 탐색 범위 수정

`data/gui_multi_moderate_pilot/`의 예비 구간에서 고도 약 7500m인 T6의 첫 관측 위상이
약 22.6초였고 초기 직진이 보이지 않았다. 모의기 화면에서도 초기 위치가 탐색 부채꼴 바깥에 있었다.
운동 잔차를 확인하거나 보정하기 전에 T6 초기 방위만 −35→−25도로 옮긴
`scenarios/multi_target_moderate_6_in_view.ini`를 별도로 만들었다. 예비 ini와 로그는 유지한다.
나머지 입력과 고정 후보 옵션·시계는 바꾸지 않았다. 수정 후 같은 시간 격자의 모델상 최소 간격은
약 3646m다. 정식 두 운용 구간은 수정한 같은 파일로 실행하며 예비 구간과 합쳐 통계를 내지 않는다.

정식 구간의 잔차를 보기 전에 예비 T1 직진 154개만으로 시간 원점 진단도 별도로 계산했다.
기존 원점에 +0.011723648초를 더하는 값이며 주기·물리 계수는 유지한다.
주 검증은 원래 고정 시계를 계속 사용한다. 예비 자료로 보정한
`multi_target_moderate_pilot_clock_candidate.json`의 결과는 보조 진단으로 구분하며
정식 구간 1·2의 값을 보고 다시 맞추지 않는다.
